# Система интеллектуального анализа данных мониторинга вузов

Информационно-аналитическая система, которая собирает открытые данные мониторинга эффективности
деятельности образовательных организаций высшего образования (Минобрнауки России), прогнозирует
положение вуза в следующем мониторинге с помощью нейронной сети и находит организации с нетипичным
профилем показателей.

## Что умеет система

| Задача | Как решается |
|---|---|
| Сбор данных | Веб-скрейпинг сайта `monitoring.miccedu.ru` (пакет `vuzmon.collect`): 2021–2025 годы, 6 127 записей «организация — год», 5 основных и 56 дополнительных показателей |
| Прогноз класса результативности на следующий год | Ансамбль многозадачных нейронных сетей на PyTorch (`models/model1.pt`) |
| Поиск нетипичных профилей, типологические группы | Шумоподавляющий автокодировщик + k-средних в скрытом пространстве (`models/model2.pt`) |
| Объяснение прогноза | Важность признаков методом перестановок, вклад признаков для отдельной организации |
| Расчёт «что будет, если…» | Пересчёт прогноза при изменённых значениях показателей |
| Документы | Справка по организации, сводная записка, протокол обучения (Word), таблица прогноза, журнал действий (Excel) |
| Обратная связь | Форма обращения к администратору (вопрос, ошибка, замечание к данным, предложение); ответы — в панели администратора |
| Загрузка наборов данных | Из файлов (ZIP-архив или пять CSV) и напрямую по ссылке; содержимое проверяется до сохранения — при ошибке называются файл, столбец и строка |
| Защита | Три роли, защита форм от подделки запросов, приостановка входа после пяти неверных паролей подряд, защитные заголовки ответов, журнал действий |

Класс результативности определяется числом основных показателей (E.1, E.2, E.3, E.4, E.8), значения которых
не ниже медианы по России: **зона риска** (0–1), **средний уровень** (2–3), **лидеры** (4–5).

## Быстрый запуск

Нужен Python 3.11–3.13. База данных, набор данных и обученные модели уже лежат в репозитории,
поэтому собирать и обучать ничего не требуется.

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows;  в Linux и macOS: source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

После запуска откройте в браузере <http://127.0.0.1:5000>.

Если порт 5000 занят, укажите другой: `python main.py --port 8080`. В macOS порт 5000 использует служба
«Приёмник AirPlay», поэтому адрес `localhost:5000` там отвечает ошибкой 403 — открывайте именно
`127.0.0.1:5000` или запустите систему на другом порту.

### Учётные записи (тестовые)

| Роль | Логин | Пароль | Возможности |
|---|---|---|---|
| Администратор | `admin` | `Admin#2026` | всё, включая пользователей, ответы на обращения, журнал действий и настройки |
| Аналитик | `analyst` | `Analyst#2026` | данные, обучение моделей, прогноз, отчёты, заметки |
| Руководитель | `viewer` | `Viewer#2026` | просмотр показателей и прогнозов, выгрузка отчётов |

После пяти неверных паролей подряд вход с этим логином приостанавливается на 10 минут.

### Проверка установки

Пока система запущена, во втором окне терминала (с тем же виртуальным окружением) выполните:

```bash
python check_install.py
```

Сценарий обращается к приложению так же, как браузер, и печатает протокол — для каждого сценария ожидаемый
и фактический результат: вход под тремя ролями и состав меню, запрет чужих разделов, построение прогноза,
выгрузка документов Word и Excel (каждый файл открывается и проверяется), сравнение организаций, проверка
настроек, защитные заголовки ответов и приостановка входа после неверных паролей — всего 20 сценариев,
с ключом `--collect` — 24. Ключи:

| Ключ | Назначение |
|---|---|
| `--url http://127.0.0.1:8080` | адрес приложения, если оно запущено на другом порту |
| `--collect` | дополнительно получить с сайта мониторинга сведения о трёх организациях и загрузить набор данных по ссылке из репозитория (нужен Интернет) |
| `--report protocol.md` | сохранить протокол в файл |
| `--wait 120` | ждать запуска приложения до 120 секунд (для автоматического запуска) |

## Данные

Источник — информационно-аналитические материалы мониторинга эффективности деятельности образовательных
организаций высшего образования: <https://monitoring.miccedu.ru/?m=vpo>. Данные получены самостоятельно,
случайные и синтетические данные не используются.

| Файл | Содержание |
|---|---|
| `institutions.csv` | паспорт организации за год: название, регион, округ, ведомство, специфика, профиль подготовки |
| `main_indicators.csv` | основные показатели E.1–E.8 (значения за 2017–2025 годы) |
| `medians.csv` | медианы по России, субъекту РФ и ведомству |
| `extra_indicators.csv` | 56 дополнительных характеристик (столбцы `p1` … `p56`) |
| `indicator_dictionary.csv` | справочник показателей |

Повторный сбор (около 30 минут, страницы кэшируются в `data/cache`):

```bash
python -m vuzmon.collect --years 2021 2022 2023 2024 2025
```

Тот же сбор запускается из раздела «Данные» веб-приложения; там же можно ограничить число организаций
для пробного запуска. Собранный или загруженный набор попадает в перечень наборов, а рабочим
(по нему строятся выборка и прогноз) становится только по явному действию и только если охватывает
не менее четырёх лет мониторинга.

### Загрузка набора по ссылке

Набор данных опубликован в этом репозитории, поэтому его можно получить напрямую по ссылке — без сбора
с сайта и без копирования файлов. Адрес каталога с файлами записан в `vuzmon/config.py` (`DATASET_URL`):
<https://raw.githubusercontent.com/sinkarev39/vuz-monitoring-analysis/main/data/monitoring>.

```python
from vuzmon.collect.crawler import load_frames_from_url
frames = load_frames_from_url()          # словарь из пяти таблиц pandas
```

То же самое делают форма «Загрузить по ссылке» в разделе «Данные» и блокнот `notebooks/01_data_collection.ipynb`
(переключатель `LOAD_FROM_URL`). Ссылка может вести на каталог с пятью CSV-файлами или на ZIP-архив с ними;
подходит и адрес страницы каталога на GitHub. Набор, загруженный из файлов или по ссылке, проверяется:
ключи и годы должны быть целыми числами, показатели — числами. Набор с ошибками не сохраняется.

## Модели

| Файл | Модель | Назначение |
|---|---|---|
| `models/model1.pt` | ансамбль из 5 многозадачных перцептронов (PyTorch) | прогноз класса на следующий год |
| `models/model2.pt` | автокодировщик (PyTorch) | нетипичные профили и типологические группы |
| `models/model3.npz` | softmax-регрессия, написанная на NumPy «с нуля» | опорная модель |
| `models/model4.joblib` | случайный лес (scikit-learn) | модель сравнения |

Разбиение по времени: обучение — данные 2021–2022 годов, валидация — 2023, тест — 2024 (класс 2025 года).

| Модель | Верных ответов (тест) | Macro-F1 | ROC-AUC | Log-loss |
|---|---|---|---|---|
| Наивный прогноз «класс не изменится» | 0,796 | 0,778 | 0,834 | 0,957 |
| Softmax-регрессия на NumPy | 0,738 | 0,724 | 0,888 | 0,630 |
| Базовая сеть 64–32, SGD | 0,757 | 0,736 | 0,899 | 0,537 |
| Одна многозадачная сеть (лучшая конфигурация) | 0,786 | 0,759 | 0,918 | 0,492 |
| **Ансамбль многозадачных сетей (`model1.pt`)** | **0,788** | **0,771** | **0,923** | **0,476** |
| Случайный лес | 0,813 | 0,789 | 0,924 | 0,496 |

Класс вуза очень инерционен, поэтому по доле верных ответов все модели близки к наивному прогнозу;
преимущество моделей — в качестве вероятностей (ROC-AUC, log-loss): они показывают, какие организации
находятся у границы класса. Подробности — в блокноте `notebooks/03_model_training.ipynb`.

Обучить все модели заново (около 5 минут на процессоре, графический ускоритель не требуется):

```bash
python -m vuzmon.ml --trials 30
```
